## 1. 앱 전체 구조 (지도)

```
모드 6: 채널/재생목록 URL + 종류
  → 목록만 조회 (flat, 빠름. 다운로드 0회)
  → DB 스냅샷 저장 (scans 1행 + scan_items N행)
  → 신규 판정: 이번에 있고 과거에 없던 video_id
  → 자막없음 조회: 최신 스캔 항목 중 success 기록 없는 것
  → 화면에 신규 목록 + 자막없음 목록 표시
```

```

--- 자막 없는 영상 5개 (빨강: 당장 받을 후보) ---

[END] 스캔 완료 (다운로드 없음 - 조건을 정해 모드 1~3으로 받으세요)
```

스캔은 절대 다운로드하지 않습니다. 자막 받기는 모드 1~3에서 조건을 정해 별도로 실행합니다.

## 3. 동작 원리 (쉽게)

- **스냅샷**: 스캔할 때마다 목록 전체(영상ID·제목·길이·종류·URL)를 DB에
  그대로 복사해 둡니다. 사진 찍어두는 것과 같습니다.
- **신규 판정**: 이번 사진에 있고, 과거 모든 사진에 없던 ID가 신규입니다.
  ID 기준이라 제목이 바뀌어도 같은 영상으로 알아봅니다.
  both 실행 시 양 탭 겹침은 중복 제거됩니다.
- **자막없음**: 최신 사진 기준으로, 자막 성공 기록이 없는 항목입니다.
  최신 사진에서 빠진 영상(삭제·비공개 추정)은 쫓지 않습니다.
- **대상 정규화**: `@x`와 `@x/videos`는 같은 곳으로, `list=` 뒤 ID가
  같으면 같은 재생목록으로 봅니다. 그래야 스캔끼리 비교가 됩니다.
- **가벼움**: 목록 조회만 해서 영상당 무거운 요청 없이 끝납니다.
