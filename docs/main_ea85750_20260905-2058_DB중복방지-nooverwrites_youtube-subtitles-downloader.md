## 2. 사용 흐름 (이번 커밋 기준)

 달라진 건 사용자 입력이 아니라 **내부 순서**입니다.

```
영상 순서가 옴
  → (신규) DB에 "이 URL+이 언어로 성공한 적 있나?" 조회 — 요청 0회
      → 있고 파일도 그대로 있으면 → "[SKIP] 이미 받음" + 다음 영상 (종료)
      → 기록은 있는데 파일이 지워졌으면 → "다시 받음" 안내 후 정상 진행
      → 언어 설정이 다르면 (ko,en 받음 vs ko 요청) → 정상 진행
  → 기존 흐름 그대로 (정보 요청 → 조건 검사 → 저장 → DB 기록)
```

## 3. 동작 원리 (쉽게)

- **장부 먼저 보기**: 도서관에서 책을 빌리기 전에 "이미 집에 있지 않나" 책장을
  보는 것과 같습니다. DB의 완료 기록이 책장 목록, 실제 파일 존재 확인이
  책장 실물 확인입니다. 둘 다 있어야 대출(요청)을 안 합니다.
- **왜 파일까지 확인하나**: DB에는 성공이라 적혀 있는데 사용자가 파일을 지웠을
  수 있습니다. 그때 스킵해 버리면 자막이 없는 채로 끝납니다.
  그래서 기록+실물 둘 다 있을 때만 스킵, 하나라도 없으면 다시 받습니다.
- **2중 안전망**: DB 스킵이 1차, yt-dlp의 `nooverwrites`(같은 파일 있으면
  덮어쓰지 않음)가 2차입니다. 1차가 유튜브 요청 자체를 없애고,
  2차는 혹시 요청이 나가도 파일 쓰기를 막습니다.
