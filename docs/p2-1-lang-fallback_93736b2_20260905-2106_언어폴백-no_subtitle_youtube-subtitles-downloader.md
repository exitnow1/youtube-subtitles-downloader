## 1. 앱 전체 구조 (지도)

```
영상 1개 처리 (download_subs_for_video)
  → (기존) DB 캐시 확인 → DB 시작 기록
  → (신규) 후보 순서표대로 최대 3라운드
       1라운드: 요청 설정 (예: ko, 자동자막 끔)
       2라운드: 자동자막 폴백 (예: ko + 자동)
       3라운드: 언어 폴백 (예: en + 자동)
  → 라운드마다: 다운로드 → 파일 있나 확인 → 있으면 저장+헤더, 없으면 다음 라운드
  → 전부 비었으면 no_subtitle 확정
```

## 2. 사용 흐름 (이번 커밋 기준)

사용자 입력은 그대로입니다. 달라지는 건 결과 종류입니다.

```
예: ko 자막 요청, 영상엔 영어 자막만 있음
  이전: 자막 0개인데도 "성공"으로 기록 (버그에 가까움)
  이번:
    1라운드 ko 수동 → 0개 → "[폴백 2/3] 자동자막 폴백"
    2라운드 ko+자동 → 0개 → "[폴백 3/3] 언어 폴백"
    3라운드 en+자동 → 저장! → "[END] 자막 저장: 제목 (언어 폴백(en+자동)로 저장)"

예: 자막 자체가 없는 영상
  → 3라운드 전부 0개 → "[자막 없음]" + 별도 목록 + DB 상태 no_subtitle
  → 실패가 아니라서 모드 4(재시도) 목록에는 안 나옴 (다시 해도 생기지 않음)
```

## 3. 동작 원리 (쉽게)

- **문제**: 이전에는 "다운로드 과정이 에러 없이 끝남 = 성공"이었습니다.
  그런데 자막 파일이 0개여도 에러가 안 나서, 자막 없는 영상이 버젓이
  성공으로 기록됐습니다.
- **해결**: 성공의 정의를 "에러 없음"에서 **"자막 파일 1개 이상 저장됨"**으로
  바꿨습니다. 매 라운드 끝에 폴더를 보고 파일이 있나 직접 셉니다.
- **폴백 순서 이유**: 수동 자막(사람 작성) → 자동자막(기계 변환) →
  영어 순입니다. 품질 좋은 것부터 물어보는 것입니다.
  `all`을 요청했으면 1라운드에서 전부를 본 것이니 추가 라운드 없음.
- **없는 영상·조건 스킵은 그대로**: `Video unavailable`이면 폴백 없이 즉시
  실패, 날짜·길이 조건 탈락이면 폴백 없이 스킵. 폴백은 "자막 언어" 문제에만
  씁니다.

## 4. 전체 그림에서 뭘 추가·수정했나

| 구분 | 위치 | 내용 |
|---|---|---|
| 추가 | 상수 `FALLBACK_LANGS = ("en",)` | 마지막 후보 언어. 바꾸려면 여기만 고치면 됨 |
| 추가 | `_build_fallback_plan()` | (언어, 자동자막, 설명) 후보 순서표 생성. `all`·이미 포함된 언어는 중복 제거 |
| 추가 | `_download_round()` | 한 후보당 최대 3회 시도(429/403 백오프 포함). 반환 `(kept, saw_429, fatal, fatal_msg)` — 기존 재시도 로직을 그대로 옮김 |
| 수정 | `download_subs_for_video()` | 라운드 반복 구조로 변경. 라운드마다 파일 존재 확인 → 있으면 헤더+성공(몇 번째 후보인지 DB 사유에 기록), 없으면 다음 후보. 전부 비면 `no_subtitle` |
| 추가 | 전역 `NO_SUB_LIST` + `finalize()` | 종료 화면에 "자막 없음"란 분리 표시 |
| 없음 | DB 스키마 | 변경 없음. 상태값에 `no_subtitle`이 추가될 뿐, 실패 조회·개수 집계는 그대로 동작 |
