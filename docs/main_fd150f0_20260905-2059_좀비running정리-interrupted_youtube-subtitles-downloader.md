# 설명서: 좀비 running 정리 (P1-2)

- 브랜치: `main` / 커밋: `fd150f0` / 일시: 2026-09-05 20:59 (KST)
- 저장소: youtube-subtitles-downloader
- 한 줄 요약: 강제종료로 DB에 `running`으로 남은 좀비 행을 시작할 때 `interrupted`로 정리. 재시도 목록을 오염시키지 않음.

---

## 1. 앱 전체 구조 (지도)

```
main() 시작
  → (신규) DB 흔적 청소 — 30분 지난 running → interrupted
  → 메뉴 1/2/3/4 → 영상마다 [DB 시작 기록(running) → ... → DB 종료 기록(success/skipped/failed)]
```

## 2. 사용 흐름 (이번 커밋 기준)

사용자가 새로 입력할 것은 없습니다. 프로그램을 켜면 자동으로:

```
DB 열기
  → "30분 넘게 running인 행 있나?" 조회 — 요청 0회, 내 컴퓨터 DB만 봄
      → 있으면 → interrupted로 도장 + "[정리] N건" 로그
      → 없으면 → 조용히 통과
  → 기존 메뉴 그대로
```

## 3. 동작 원리 (쉽게)

- **문제**: 영상 처리 중에 Ctrl+C·정전·강제종료를 하면, "시작"은 적혔는데
  "종료"가 안 적힌 `running` 행이 영원히 남습니다. 좀비입니다.
  이게 쌓이면 DB가 거짓말을 합니다 ("지금 10개가 도는 중"인데 실제론 0개).
- **구분법**: 시작 시각이 30분 넘게 지났는데도 끝나지 않았으면, 살아있는
  작업이 아니라 죽은 흔적입니다. 방금 시작된 `running`(정상 진행 중)은
  건드리지 않습니다. 기준 시각은 ISO 문자열(`2026-09-05T20:00:00`)이라
  문자열 비교가 곧 시간 비교가 됩니다.
- **왜 failed로 안 바꾸나**: 실패는 "해 봤는데 안 됨"이고, interrupted는
  "끝까지 해 보지도 못함"이라 의미가 다릅니다. 모드 4(실패 재시도)에
  섞으면 사용자가 원치 않은 재시도를 하게 되니 분리합니다.
- **이어서 하려면**: 원래 모드(채널·재생목록)를 그대로 다시 돌리면 됩니다.
  P1-1 캐시 덕분에 이미 받은 영상은 건너뛰고, 미완료분만 처리됩니다.
