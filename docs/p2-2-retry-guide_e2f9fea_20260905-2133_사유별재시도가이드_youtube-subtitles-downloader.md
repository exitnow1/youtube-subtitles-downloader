## 3. 동작 원리 (쉽게)

- **문제**: 이전에는 실패 사유가 달라도(없는 영상 vs 일시 차단) 똑같은
  재시도 절차를 밟았습니다. 없는 영상은 골라도 소용없고, 429는 바로
  재시도하면 또 막힙니다. 사용자가 사유를 읽고 직접 판단해야 했습니다.
- **해결**: `recommend_retry()`가 사유 문자열을 보고 4가지로 분류합니다.
  없는 영상(`영상 없음...`) → skip, 429 → wait, 403 → cookie, 나머지 → now.
  분류 결과를 목록에 표시하고, 상황에 맞는 다음 질문(제외/예약)을 먼저
  건넵니다. 답은 항상 사용자가 고릅니다 (자동 제외 아님).
- **보너스 수정**: 안내문에 쓰인 `—`(긴 대시)가 Windows 콘솔(cp949)에서
  출력 크래시를 일으키는 것을 테스트 중 발견해 `-`로 교체했습니다.
  코드 내 동일 문자 8곳 전부 수정 + cp949 불가 문자 전수 확인.

## 4. 전체 그림에서 뭘 추가·수정했나

| 구분 | 위치 | 내용 |
|---|---|---|
| 추가 | `recommend_retry()` | 사유 → (행동, 안내문). 순수 함수라 테스트 쉬움 |
| 수정 | `run_retry()` 목록 출력 | 항목별 표시 + 가이드 줄 + 요약 줄 |
| 수정 | `run_retry()` 선택 후 | 없는 영상 제외 제안 → 429 예약 제안 → 기존 예약 질문 순. 둘 다 거부하면 기존과 동일하게 동작 |
| 수정 | em-dash 8곳 → 하이픈 | 콘솔 출력 크래시 방지 (코드 전체 검사 완료) |
| 없음 | 실제 재시도 로직·DB·차단기 | 손대지 않음 |
