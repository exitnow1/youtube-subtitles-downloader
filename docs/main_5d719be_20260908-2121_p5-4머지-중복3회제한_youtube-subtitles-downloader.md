## 1. 앱 전체 구조 (지도)

```
영상 처리 시작
  → (기존) DB 완료 기록 + 파일 존재 → "이미 받아둠" 스킵
  → (신규) 같은 URL+언어 누적 성공 횟수 조회
      → 3회 미만: 정상 진행
      → 3회 도달: "[SKIP] 중복 3회(최대 3회)" + 요청 0회 종료
```

## 2. 사용 흐름 (이번 커밋 기준)

사용자 입력 변화 없음. 같은 영상을 파일을 지웠다 다시 받는 식으로
3번 성공하면, 4번째부터는 자동으로 건너뜁니다.
언어가 다르면 별도 카운트(ko 3회 ≠ en 3회)라 정상 진행됩니다.

## 3. 동작 원리 (쉽게)

- **문제**: P1-1 캐시는 "파일이 있으면" 스킵하지만, 파일을 지우면
  몇 번이고 다시 받았습니다. 실수 반복·테스트 반복이 요청 낭비로 이어짐.
- **해결**: DB 성공 행 자체가 누적 장부입니다. 시작 전에
  `같은 URL+같은 언어+성공` 행 개수를 셉니다. 상한(기본 3, 설정 변경 가능)에
  닿으면 다운로드 함수를 호출하지도 않습니다.
- **실패는 제외**: 실패는 "못 받은 것"이니何번을 실패해도 카운트에 안 들어갑니다.
  재시도(모드 4)가 막히지 않는 이유입니다.
- **스킵은 DB에 새 행 없음**: 아무것도 시도하지 않았으니 장부에 적을 것도
  없습니다. 기존 cached 스킵과 동일한 처리입니다.
