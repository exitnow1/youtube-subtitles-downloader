# 설명서: 없는 영상 즉시 실패 처리

- 브랜치: `main` / 커밋: `3de46ce` / 일시: 2026-09-05 21:04 (KST)
- 저장소: youtube-subtitles-downloader
- 한 줄 요약: 삭제·비공개·찾을 수 없는 영상은 3번 재시도하지 않고 1번으로 끝냄. 사유는 실패 목록과 DB에 "영상 없음"으로 기록.

---

## 1. 앱 전체 구조 (지도)

```
영상마다 [DB 시작 기록 → 정보 요청 → ...]
                  ↓ 실패 시
            기존: 무조건 최대 3회 재시도 (어떤 오류든)
            이번: "없는 영상" 신호면 1회로 종료 + 사유 기록
```

## 2. 사용 흐름 (이번 커밋 기준)

사용자 입력은 그대로입니다. 내부에서만 달라집니다.

```
다운로드 시도 중 오류 발생
  → 오류 메시지에 "Video unavailable / Private video / 404 ..." 포함?
      → 예: "[영상 없음] 재시도 없이 실패 처리" 로그
            + FAIL_LIST에 "영상 없음(삭제/비공개/찾을 수 없음): ..." 기록
            + DB 행에도 같은 사유 기록 (시작·종료 시각 포함)
      → 아니오: 기존대로 429/403/일반 백오프 후 최대 3회 재시도
```

## 3. 동작 원리 (쉽게)

- **문제**: 이미 지워진 영상은 100번을 물어봐도 안 살아납니다.
  그런데 기존 코드는 모든 오류를 3번씩 재시도해서, 없는 영상 10개면
  30번의 헛요청 + 대기 시간이 쌓였습니다. 차단 카운터에도 안 좋습니다.
- **해결**: 유튜브가 돌려주는 오류 메시지에는 "없는 영상" 전용 신호가
  있습니다 (`Video unavailable`, `Private video`, `404` 등 10종).
  이 신호가 보이면 재시도 없이 바로 실패로 확정합니다.
  429·403·네트워크 오류는 살아날 수 있으니 기존 재시도 유지.
- **기록**: 실패 사유가 "영상 없음..."으로 시작하므로, 나중에 DB나
  실패 파일을 보면 "차단 때문인지, 원래 없는 영상인지" 바로 구분됩니다.

## 4. 전체 그림에서 뭘 추가·수정했나

| 구분 | 위치 | 내용 |
|---|---|---|
| 추가 | 모듈 상수 `UNAVAILABLE_PATTERNS` | 없는 영상 신호 10종 (소문자 비교) |
| 수정 | `download_subs_for_video()` 예외 처리 첫 분기 | 없는 영상 신호 → 재시도 없이 `FAIL_LIST` + DB `failed` 기록 후 `("failed", False)` 반환. 차단기에 영향 없음(429 아님) |
| 없음 | 그 외 모든 로직 | 손대지 않음 |

  기존대로 3회 재시도 유지 + 사유에 `영상 없음` 없음
